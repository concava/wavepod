# 0009 — Evaluation harness (`podeval`)

- Status: **Accepted** — harness built; thresholds become absolute gates once the references are verified
- Date: 2026-10-19

## Question

How do we score every engine and pipeline change on real podcasts, in CI, without putting copyrighted audio or text
in the repository?

## Decision

`eval/podeval` (Python, its own `uv` project) drives the same Swift runner as Phase 0 (`bench/swift`, `wavebench`)
over the golden set in [0007](0007-golden-set.md). Python is used for scoring only, because the standard metric
implementations live there (`jiwer`, `pyannote.metrics`, `meeteval`, whisper's text normalizers).

| Step | What it does |
|---|---|
| `fetch` | Resolves each link with `wavepod-resolve` (yt-dlp for YouTube), downloads once into the cache, pins the file's SHA-256 in the manifest, decodes to 16 kHz mono and cuts the 20-min scored window. |
| `draft` | Diarizes each window (FluidAudio) and transcribes every speaker turn short-form with openai/whisper large-v3 → `ref.txt` with `status: draft`. For a show with a published, speaker-labelled transcript it also aligns that text to the draft's turns → `ref-published.txt`. |
| `run` | Runs each engine on every window and every full episode, under `/usr/bin/time -l`. |
| `score` | Window: WER per engine, DER, cpWER per ASR + diarization pipeline, % of reference turns with the correct speaker name. Full episodes: RTF, peak footprint and RSS, longest stretch without words. |
| `check` | Compares with `eval/golden/baseline.json`; exits 1 on a regression. |
| `baseline` | Stores the current summary as the baseline (metric numbers only; committed). |

What lives where:

- **Repository**: the manifest (links, GUIDs, SHA-256, windows, reference status), the baseline numbers, the code.
- **Cache only** (`~/Library/Caches/wavepod-golden`, or `WAVEPOD_GOLDEN`): audio, references, engine output.

## Choices

- **Pinned audio.** Hosts with dynamic ad insertion (Megaphone, Podscribe) serve a different file per download, which
  shifts every timestamp. The first download is pinned by SHA-256; a later mismatch stops `fetch` unless
  `--accept-new`, which marks the reference as missing. The CI runner keeps its cache.
- **Scored window vs full run.** References cover a 20-min window; the full episode runs for speed, memory and
  stability. Windows are scored from a run on the window audio itself, so a window's first and last seconds miss
  context the full run would have. When the Phase 3 pipeline writes word timings for whole episodes, scoring moves to
  slicing the full run.
- **Speaker attribution for cpWER** uses the word-to-turn rule of [0003](0003-diarization.md) (turn covering the
  word's midpoint, shortest if several, else nearest within 0.5 s, else the previous word's speaker), written in
  Python here and in Swift in Phase 3. Both must agree; the Phase 3 tests reuse this behaviour.
- **Speaker names** stay empty until Phase 4 names speakers; the metric counts only when the hypothesis labels are
  names that appear in the reference.
- **Dropped audio.** The longest stretch without a word in each full run is reported; over 30 s is flagged (music
  or dropped audio), following the rule that the pipeline may cut but never silently drop audio.
- **Draft bias.** The draft comes from openai/whisper large-v3, the reference engine. Until a person corrects it, the
  reference engine scores near 0 % and the others are measured against Whisper, not against what was said. Hence:
  - a draft reference never triggers the absolute gate below, only regressions against a baseline made on the same
    draft;
  - the corrector listens to everything, not only to lines that look wrong.
- **Draft device.** openai/whisper on CPU: on MPS it was 3.4× slower here (57.7 s vs 16.9 s for 30 s, M3).

## Gates (`podeval check`)

Regression, against the committed baseline on the same reference status:

- WER +1.0 point, cpWER +1.5, DER +1.0 (per episode and engine).
- RTF ×1.3 (wall-clock noise), peak footprint ×1.2.

Absolute, on verified references only: the shipping engine (Parakeet) within **1.5 WER points** of openai/whisper
large-v3 on the same audio ([0002](0002-asr-engine.md) decision rule). The diarization rule of
[0003](0003-diarization.md) (DER within 2 points of pyannote) joins when the pyannote reference runs.

## CI

`.github/workflows/podeval.yml` runs on a self-hosted Apple Silicon runner labelled `golden` that holds the cache:
`./eval/podeval run && ./eval/podeval score && ./eval/podeval check`. It is manual (`workflow_dispatch`) and nightly,
not per push: a full run is ~11 h of audio. A per-push subset (windows only) is a Phase 3 follow-up.
